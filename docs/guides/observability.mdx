Membrane exposes behavioral metrics via `GetMetrics` and ships a comprehensive evaluation suite covering retrieval quality, revision semantics, decay curves, trust gating, and vector-aware recall.

## GetMetrics

`GetMetrics` returns a point-in-time `*metrics.Snapshot`. The daemon's Postgres path uses a fixed number of aggregate queries instead of hydrating every record. gRPC results are filtered by the server's `read_max_sensitivity` and `read_scopes` policy, so unauthorized records do not contribute to counts, audit-derived metrics, payload-derived metrics, or embedding coverage. The trusted in-process `m.GetMetrics` method retains full-store visibility; use `m.GetMetricsForTrust` when an in-process caller needs the same explicit visibility boundary.

<Tabs>
  <Tab title="Go">
    ```go
    snap, err := m.GetMetrics(ctx)
    if err != nil {
        log.Fatal(err)
    }
    fmt.Printf("Total: %d, Usefulness: %.2f\n", snap.TotalRecords, snap.RetrievalUsefulness)
    ```
  </Tab>
  <Tab title="gRPC">
    Call the `GetMetrics` gRPC method (no request body required). The `snapshot` response field is a `google.protobuf.Value` containing the metrics object.
  </Tab>
</Tabs>

## Metrics reference

| Metric | Type | Description |
|--------|------|-------------|
| `collected_at` | `string` | RFC 3339 timestamp when the snapshot was collected |
| `total_records` | `int` | Total records visible to the snapshot's policy |
| `records_by_type` | `map[string]int` | Count of records per memory type |
| `avg_salience` | `float64` | Mean salience across policy-visible records |
| `avg_confidence` | `float64` | Mean confidence across policy-visible records |
| `salience_distribution` | `map[string]int` | Record counts in 0.2-wide salience buckets |
| `active_records` | `int` | Records with `salience > 0` |
| `pinned_records` | `int` | Records with `lifecycle.pinned = true` |
| `total_audit_entries` | `int` | Total audit entries across policy-visible records |
| `embedding_model` | `string` | Configured embedding model for vector coverage reporting |
| `embedded_records` | `int` | Records with usable embeddings for the configured model |
| `missing_embeddings` | `int` | Records missing current-model embeddings |
| `embedding_coverage` | `float64` | Fraction of records with current-model pgvector embeddings |
| `memory_growth_rate` | `float64` | Fraction of records created in the last 24 hours |
| `retrieval_usefulness` | `float64` | Ratio of reinforce audit actions to total audit entries |
| `competence_success_rate` | `float64` | Average `SuccessRate` across all competence records |
| `plan_reuse_frequency` | `float64` | Average `ExecutionCount` across all plan_graph records |
| `revision_rate` | `float64` | Fraction of audit entries that are supersede, fork, or merge operations |

### Interpreting key metrics

**`retrieval_usefulness`** — A high value (near 1.0) means retrieved records are frequently reinforced after use, indicating good retrieval quality. A low value may indicate the retrieval is surfacing records that aren't actually useful.

**`memory_growth_rate`** — Tracks how fast the substrate is growing. A rate near 1.0 means almost all records were created in the last 24 hours, which may indicate runaway ingestion or a new agent start.

**`revision_rate`** — Measures how often the knowledge base is being revised. A very low rate may indicate the agent isn't learning from feedback; a very high rate may indicate instability in the knowledge base.

**`embedding_coverage`** — Tracks whether records have usable current-model pgvector embeddings. The collector normalizes impossible provider stats so coverage stays between `0.0` and `1.0`. If coverage drops after ingestion or a model change, retrieval can look healthy while quietly falling back to salience for many records.

## Evaluation suite

The eval suite covers functional correctness across all major subsystems.

### Run everything

```bash
make eval-all
```

This runs all Go-based eval tests, the vector end-to-end evaluation script, and the lifecycle comparison eval. The vector and lifecycle evals require `MEMBRANE_POSTGRES_DSN` and `MEMBRANE_EMBEDDING_API_KEY`.

The scheduled GitHub eval workflow uses the same Make targets. It requires the `MEMBRANE_EMBEDDING_API_KEY` repository secret and fails early if the secret is missing, so eval runs cannot silently skip the pgvector-backed checks.

### Targeted capability evals

```bash
make eval-typed          # Memory type handling
make eval-revision       # Revision semantics
make eval-decay          # Decay curves and pruning
make eval-trust          # Trust-gated retrieval
make eval-competence     # Competence learning
make eval-plan           # Plan graph operations
make eval-vector         # Postgres + pgvector recall metrics
make eval-lifecycle      # Lifecycle semantics against flat vector search
make eval-consolidation  # Episodic consolidation
make eval-metrics        # Observability metrics
make eval-invariants     # System invariants
make eval-grpc           # gRPC endpoint coverage
```

Each target maps to a `go test` run against the `./tests` package with a specific `-run` filter.

## Recall regression tests

The recall regression test validates that the retrieval layer returns expected records given a known corpus:

```bash
go test ./tests -run TestRetrievalRecallAtK
```

This test checks recall@k for a fixed set of records and queries, failing if recall drops below the configured threshold. Use it as a canary to detect regressions in retrieval ordering or trust filtering.

## Vector end-to-end metrics

The vector E2E evaluation measures recall, precision, MRR, and NDCG over a synthetic corpus with Postgres + pgvector-backed retrieval. It requires the same database/vector substrate as the daemon plus an embedding API key; local sentence-transformer fallback mode is intentionally not supported. Dataset records can cover all six memory types, including explicit `entity` records with aliases and external identifiers, so evals can exercise entity-root retrieval directly rather than relying only on entities inferred from semantic observations. When a record omits `text`, the eval CLI builds embedding input from the typed payload fields, so entity aliases and identifiers still participate in pgvector ranking.

<Steps>
  <Step title="Start Postgres + pgvector">
    ```bash
    export MEMBRANE_POSTGRES_PASSWORD="$(openssl rand -hex 24)"
    export MEMBRANE_POSTGRES_DSN="postgres://membrane:${MEMBRANE_POSTGRES_PASSWORD}@127.0.0.1:5432/membrane_test?sslmode=disable"
    docker compose up -d
    ```
  </Step>
  <Step title="Configure embeddings">
    ```bash
    export MEMBRANE_EMBEDDING_API_KEY="..."
    export MEMBRANE_EMBEDDING_ENDPOINT="https://openrouter.ai/api/v1/embeddings"
    export MEMBRANE_EMBEDDING_MODEL="openai/text-embedding-3-small"
    export MEMBRANE_EMBEDDING_DIMENSIONS="1536"
    ```
  </Step>
  <Step title="Run the eval">
    ```bash
    make eval
    ```

    This invokes `tools/eval/run.sh`, which ingests the eval corpus into Postgres, stores embeddings in pgvector, and measures retrieval metrics at multiple k values. Missing `MEMBRANE_POSTGRES_DSN` or `MEMBRANE_EMBEDDING_API_KEY` fails fast.
  </Step>
  <Step title="Check the results">
    The script reports `recall@k`, `precision@k`, `MRR@k`, and `NDCG@k` for flat RAG and Membrane, then fails with a non-zero exit code if any Membrane metric falls below its threshold.
  </Step>
</Steps>

The eval CLI rejects invalid quality-gate configuration before opening Postgres: `k` and embedding dimensions must be positive, metric thresholds must be finite values between `0.0` and `1.0`, and the embedding endpoint/model strings must be non-empty. Embeddings returned by the provider must match the configured dimensions, contain only finite values, and include at least one non-zero component.

### Metric definitions

| Metric | Description |
|--------|-------------|
| `recall@k` | Fraction of relevant records found in the top-k results |
| `precision@k` | Fraction of top-k results that are relevant |
| `MRR@k` | Mean reciprocal rank of the first relevant result in top-k |
| `NDCG@k` | Normalized discounted cumulative gain; measures ranking quality |

### Lifecycle comparison eval

```bash
make eval-lifecycle
```

This target runs `cmd/membrane-eval-lifecycle` against the same Postgres DSN and embedding configuration. It compares Membrane's revision, reinforcement, supersession, and decay behavior against flat pgvector similarity search.

### Environment variable overrides

Thresholds can be overridden via environment variables:

| Variable | Default | Description |
|----------|---------|-------------|
| `MEMBRANE_EVAL_MIN_RECALL` | `0.90` | Minimum acceptable recall@k |
| `MEMBRANE_EVAL_MIN_PRECISION` | `0.20` | Minimum acceptable precision@k |
| `MEMBRANE_EVAL_MIN_MRR` | `0.90` | Minimum acceptable MRR@k |
| `MEMBRANE_EVAL_MIN_NDCG` | `0.90` | Minimum acceptable NDCG@k |
